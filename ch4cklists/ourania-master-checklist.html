1. DATA ENTRY & CHART SETUP

1.1 Birth Data Input

  • Name, birth date, birth time, birth location text fields — all present in ChartSetupPanel
  • Geocoder integration (city-name to lat/lon lookup) — Geocoder.java wired in (Nominatim + timeapi.io)
  • "The Sky Now" quick-fill button (current date/time/location)
  • Home location memory and "Set Home" button
  • Birth time accuracy flag / Rodden rating — distinguish rectified, approximate, or unknown times from exact ones OPEN
  • Place-name autocomplete / typeahead dropdown — current field is plain text requiring exact spelling OPEN
  • Timezone disambiguation UI — the geocoder may return a wrong TZ for ambiguous city names; no user confirmation step exists OPEN
  • Offline atlas — no offline city database; the app cannot cast a chart without a network connection OPEN
  • Historic DST / pre-1970 local mean time accuracy — zone resolved from geocoded location; no evidence of a historic-rules test corpus OPEN
  • Timezone override (manual) — auto-detected from location only; no manual override OPEN
  • Default placeholder chart (Greenwich Noon 2000) — present but indistinguishable from a chart with a real time; affects progressed angles, solar arc precision INCOMPLETE

  • Progressed chart tri-wheel — natal inner, secondary progressions middle, transits outer (engine data exists; GUI not yet drawn) OPEN

  • Draconic charts — node-relocated zodiac; cheap to add given existing harmonic machinery OPEN
  • Relocation chart — relocated angles for a new place OPEN

1.3 Chart Persistence

  • Save / Load natal charts by name (saved_charts.properties)
  • Saved charts directory in side panel (ProfileListPanel)
  • Load saved chart as Chart A or Chart B for synastry
  • Delete & rename saved charts — charts can be saved and loaded but never removed or renamed from the interface OPEN
  • Profile metadata — name, date, time and place only; no notes, tags, relationship type, or birth-time accuracy rating OPEN
  • Search & grouping — name search exists; no folders, tags, or filtering by chart attributes OPEN
  • Multi-user / practitioner separation — one flat chart book; no separation between personal, client and research sets OPEN
  • Chart export — print or PDF / image of the wheel and interpretation text OPEN
  • Import from standard formats (AAF / ADB / Astrodienst .dat / Solar Fire) — no import path exists OPEN

19. PENDING DESIGN DECISIONS (David's Calls)

These items cannot be built without a named decision. Each one changes what a user reads.
  • Returns scope: read whole return chart or only angles? (Mercury-stations inconsistency is the same question — settle both together)
  • Quincunx orb cap: cap at 1.0° for all 6 minor aspects, or choose differently? Needs a named source for any value taken.
  • Asteroid-to-asteroid aspect prose: write 60 cells, or leave empty? Decision was planets-only for patterns; same logic applies here.
  • Tension body restriction: restrict TensionRelease to planets + Chiron (TENSION_BODIES), or rank, or leave all 29 points? Currently 9 lines in 10 are not between planets.
  • Synastry angle-click direction: Chart A's angle → natal reading, Chart B's angle → cross-chart reading. Make consistent, or document intentional asymmetry?
  • Topics reporting cut: what fraction of topics should read as "unremarkable"? Currently ~4.5% (margin 0.06). Ranges from 4.5% to 44.3% — a product question.
  • Anaretic degree definition: exactly 29°00'–29°59', or tolerance either side of the cusp? Does 0° count as the same condition or a different one? Cite a source.
  • Solar return reading: companion to returns-scope above — already outstanding.
  • Convergence weighting redesign: atLeast(n) form is meaningless (all targets score 3+). Needs weighting redesign or a different model before releasing can be wired in.
  • Tri-wheel aspect lines: sky ring draws glyphs; should aspect lines be drawn to Chart A and B? Plumbing is in place.
  • Horary mode framing: the traditional apparatus (dignity, sect, joys, transfer of light, collection) exists — present it as a judgement tool?
  • Swiss Ephemeris & corpus licensing: AGPL vs paid commercial; 600,000+ interpretation entries with no recorded provenance. Must be settled before any distribution.
