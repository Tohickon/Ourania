# the entry gets tightened. An entry with no number still works and is named as unguarded.

EphemerisFailureCheck 1      # 1 in Part C: on a chart whose ephemeris will not read, the Sun comes back MARKED OK CARRYING THE MOON'S LONGITUDE - 39.447 where it belongs at 101.593. Narrowed 2026-09-28 to a three-line reproduction: ask for the Sun first on a damaged ephemeris and it fails correctly (rc -1); run ChartFrame's prologue first (the SE_ECL_NUT call and swe_houses are enough) and the same request returns rc 258, SEFLG_SWIEPH, with the Moon's value. TWO CANDIDATE GUARDS ARE DEAD BY MEASUREMENT: serr does not discriminate (the Sun, the Moon and the North Node all carry the same 'semo_18.se1 not found' text, and the latter two are correct), and neither does rc (the wrong Sun and a correct Sun both return 258/SWIEPH). The lead is in the library, not the app: SwissEph.swecalc's Sun branch sets xp = pedp.xreturn, the EARTH's buffer, because SEI_SUN == SEI_EARTH internally - and the Moon's computation writes through that same slot. Next step is reading the SWIEPH path below that assignment for a failure that does not return ERR. Deliberately not guessed at: a wrong fix here does not crash, it silently changes positions.
